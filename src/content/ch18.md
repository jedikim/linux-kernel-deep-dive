::: {.lead}
가상 주소는 얼마든지 약속할 수 있지만 물리 메모리는 정해진 양뿐입니다. 커널은 그것을 4KB 조각으로 나눠 조각마다 장부를 적고, 요청이 올 때마다 내주고, 모자라면 덜 쓰이는 조각을 골라 거둬 갑니다. 어떻게 적는가, 어떻게 나눠 주는가, 무엇을 거두는가. 세 질문 모두 지난 몇 년 사이에 답이 바뀌었습니다. 장부는 페이지에서 폴리오로, 객체 할당자는 세 구현에서 하나로, 스왑 캐시는 트리에서 배열로 옮겨 갔습니다. 이 장은 v7.3의 답을 소스에서 읽습니다.
:::

::: {.goals}
- 폴리오는 `struct page`의 어떤 문제를 풀려고 생겼는가?
- 버디 할당자는 큰 블록을 어떻게 쪼개고 다시 합치는가?
- `GFP_KERNEL`과 `GFP_ATOMIC`은 할당 경로의 어디에서 갈리는가?
- v7.3의 SLUB에서 `kmalloc()`의 빠른 경로는 무엇을 건드리는가?
- 회수는 어떤 페이지를 먼저 버리고, 그 판단의 근거를 어디서 얻는가?
- 회수로도 메모리를 만들지 못하면 OOM 킬러는 누구를 고르는가?
:::

## 페이지와 폴리오 {#folio}

물리 메모리는 4KB짜리 **페이지 프레임**으로 나뉘고, 프레임마다 `struct page`가 하나씩 있습니다. 이 구조체들의 배열이 [17장](ch17.html)의 vmemmap 영역에 놓여 있어서, 프레임 번호(PFN)와 `struct page`의 주소는 덧셈 한 번으로 오갑니다. x86-64의 흔한 설정에서 `struct page`는 64바이트입니다. 메모리 16GB에 프레임이 약 400만 개이므로 장부만 256MB를 씁니다. 그래서 이 구조체는 한 바이트도 허투루 쓰지 않습니다. 같은 자리를 용도에 따라 다르게 읽는 union으로 이루어져 있습니다. 페이지 캐시의 페이지일 때는 `mapping`과 오프셋으로, 버디 할당자의 빈 페이지일 때는 리스트 노드와 블록 크기로 읽습니다.

커널은 연속한 2^n^개의 페이지를 한 덩어리로 다루기도 합니다. 이것이 **복합 페이지**(compound page)입니다. 첫 페이지가 head이고 나머지는 tail입니다. tail의 `struct page`는 `compound_info` 필드의 비트 0을 세워 "나는 tail"임을 표시하고 head를 가리킵니다.

여기서 문제가 생겼습니다. `struct page *`를 받은 함수는 그것이 홑 페이지인지, head인지, tail인지 타입만으로는 알 수 없습니다. 참조 카운트와 플래그는 head에만 의미가 있으므로, 함수마다 "혹시 tail이면 head를 찾아라"는 `compound_head()` 호출이 끼어들었습니다. 빠뜨리면 tail의 엉뚱한 필드를 고치는 버그가 됩니다.

```{.c file="include/linux/mm_types.h" line="404"}
struct folio {
	/* private: don't document the anon union */
	union {
		struct {
	/* public: */
			memdesc_flags_t flags;
			union {
				struct list_head lru;
				/* ... */
			};
			struct address_space *mapping;
			union {
				pgoff_t index;
				unsigned long share;
			};
			/* ... */
			atomic_t _mapcount;
			atomic_t _refcount;
			/* ... */
	/* private: the union with struct page is transitional */
		};
		struct page page;
	};
	/* ... */
};
```

**폴리오**(folio)는 "tail이 아닌 페이지에서 시작하는, 크기가 2의 거듭제곱인 페이지 묶음"입니다. 홑 페이지도 크기 1인 폴리오입니다. 읽을 곳은 두 군데입니다.

- 폴리오는 새 메모리를 차지하지 않습니다. head의 `struct page`와 같은 자리를 다른 타입으로 읽습니다(`struct page page`와의 union). 주석은 이 겹침이 과도기적(transitional)이라고 적고 있습니다.
- `flags`, `lru`, `mapping`, `_refcount`는 묶음 **전체**에 대한 것입니다. 락을 잡거나 참조를 올리거나 LRU에 넣는 일은 폴리오 단위로 합니다.

::: {.fig src="page-folio.svg"}
연속한 네 프레임으로 이루어진 폴리오. `struct folio`는 head의 `struct page`와 같은 메모리이고, tail의 `compound_info`는 head를 가리킵니다.
:::

`page_folio(page)`는 어떤 페이지든 그것이 속한 폴리오를 돌려줍니다. 폴리오를 받는 함수는 다시 확인할 필요가 없습니다. `folio_nr_pages()`와 `folio_order()`가 크기를 알려 줍니다.

::: {.design}
폴리오는 새 기능이 아니라 **불변식을 타입에 담은 것**입니다. "이 포인터는 tail을 가리키지 않는다"는 약속을 주석이나 실행 중 검사 대신 타입 이름으로 표현했습니다. 그러면 검사는 타입이 바뀌는 경계(`page_folio()`)에서 한 번만 하면 되고, 그 안쪽 함수들에서 반복하던 `compound_head()`가 사라집니다. 잘못된 포인터를 넘기는 코드는 컴파일이 되지 않습니다. 전환은 한 번에 하지 않았습니다. 5.16에 타입을 들여온 뒤 페이지 캐시, 파일시스템, 회수 코드를 서브시스템 단위로 옮겼고, v7.3에도 `struct page`를 받는 옛 인터페이스가 남아 있습니다. 같은 방식으로 슬랩에는 `struct slab`, 페이지 테이블에는 `struct ptdesc`라는 타입이 생겨, `struct page`가 하던 여러 역할을 하나씩 떼어 내고 있습니다.
:::

### 큰 폴리오: THP와 mTHP

폴리오의 실질적인 쓸모는 큰 단위입니다. 4KB 512개 대신 2MB 폴리오 하나를 다루면 LRU 조작도, 락도, 페이지 폴트도 512분의 1로 줄어듭니다. **THP**(transparent huge page)는 익명 메모리에 2MB 폴리오를 할당해 PMD 항목 하나로 매핑합니다. 프로그램은 아무것도 하지 않아도 되고, 커널 스레드 `khugepaged`가 흩어진 작은 페이지를 뒤늦게 큰 폴리오로 합쳐 주기도 합니다. **mTHP**는 그 사이의 크기입니다. 16KB, 64KB 같은 폴리오를 할당하되 매핑은 PTE로 합니다. [17장](ch17.html)에서 본 `alloc_anon_folio()`가 허용된 크기 가운데 가장 큰 것부터 시도합니다. 전체 스위치는 `/sys/kernel/mm/transparent_hugepage/enabled`이고, 크기별 허용 여부는 그 아래 `hugepages-<크기>kB/enabled`로 정합니다. 페이지 캐시에서는 파일시스템이 허용한 범위에서 미리 읽기가 큰 폴리오를 만듭니다.

hugetlbfs는 이름이 비슷하지만 다른 장치입니다. 관리자가 미리 떼어 둔 풀에서 큰 페이지를 주고, 그 페이지는 회수되지도 스왑되지도 않습니다.

## 노드와 존 {#zones}

물리 메모리는 두 겹으로 묶여 있습니다. 바깥은 **노드**입니다. NUMA 시스템에서 CPU 소켓에 가까운 메모리 한 덩어리가 노드 하나이고, `pg_data_t`가 대표합니다. 안쪽은 **존**(zone)입니다. 주소 범위에 따라 쓸 수 있는 용도가 달라서 나눕니다.

| 존 | x86-64에서의 범위 | 용도 |
|---|---|---|
| `ZONE_DMA` | 16MB 아래 | 24비트 주소만 다루는 옛 장치 |
| `ZONE_DMA32` | 4GB 아래 | 32비트 주소만 다루는 장치 |
| `ZONE_NORMAL` | 그 위 전부 | 일반 용도 |
| `ZONE_MOVABLE` | 설정에 따라 | 옮길 수 있는 페이지만. 메모리 핫플러그용 |
| `ZONE_DEVICE` | 장치 메모리 | 영구 메모리, GPU 메모리처럼 `struct page`만 필요한 영역 |

존마다 빈 페이지 목록과 **워터마크** 세 개가 있습니다. 빈 페이지가 `low` 아래로 내려가면 회수 스레드 `kswapd`가 깨어나 `high`가 될 때까지 회수합니다. `min` 아래는 비상용이라 보통의 할당은 건드리지 못합니다.

::: {.fig src="node-zone-freearea.svg"}
노드 안의 존, 존 안의 `free_area` 배열과 워터마크. 빈 페이지는 블록 크기(order)별로 다른 목록에 걸려 있습니다.
:::

::: {.lab}
존별로 크기마다 빈 블록이 몇 개인지 봅니다.

```console
$ cat /proc/buddyinfo
Node 0, zone    DMA32   1205    984    712    403    188     77     31     12      5      2    301
Node 0, zone   Normal  18332   9120   4411   1876    702    241     83     27      9      3     12
...
```

숫자 열한 개가 order 0부터 10까지의 빈 블록 수입니다. 오른쪽 열이 0에 가까워지면 큰 연속 메모리를 구하기 어렵습니다. 워터마크는 `/proc/zoneinfo`에 페이지 수로 나옵니다.

```console
$ grep -A4 'zone   Normal' /proc/zoneinfo
Node 0, zone   Normal
  pages free     243611
        boost    0
        min      16904
        low      21130
```

전체 그림은 `/proc/meminfo`에 있습니다. `MemFree`는 버디의 빈 페이지이고, `MemAvailable`은 거기에 쉽게 회수할 수 있는 페이지 캐시와 슬랩(`SReclaimable`)을 더한 추정치입니다. "쓸 수 있는 메모리"를 볼 때는 뒤쪽을 봅니다. `Cached`는 페이지 캐시, `AnonPages`는 익명 메모리, `Slab`은 슬랩 할당자가 쥔 양입니다.

## 버디 할당자 {#buddy}

페이지 단위의 할당을 맡는 것이 **버디 할당자**(buddy allocator)입니다. 빈 메모리를 2^order^ 페이지 크기의 블록으로 관리합니다.

```{.c file="include/linux/mmzone.h" line="30"}
#ifndef CONFIG_ARCH_FORCE_MAX_ORDER
#define MAX_PAGE_ORDER 10
#else
#define MAX_PAGE_ORDER CONFIG_ARCH_FORCE_MAX_ORDER
#endif
/* ... */
struct free_area {
	struct list_head	free_list[MIGRATE_TYPES];
	unsigned long		nr_free;
};
```

존마다 `free_area`가 order 0부터 `MAX_PAGE_ORDER`까지 11개 있습니다. 가장 큰 블록은 1024페이지, 4MB입니다. 요청이 오면 그 크기의 목록부터 위로 올라가며 빈 블록을 찾습니다.

```{.c file="mm/page_alloc.c" line="1900"}
static __always_inline
struct page *__rmqueue_smallest(struct zone *zone, unsigned int order,
						int migratetype)
{
	unsigned int current_order;
	struct free_area *area;
	struct page *page;

	/* Find a page of the appropriate size in the preferred list */
	for (current_order = order; current_order < NR_PAGE_ORDERS; ++current_order) {
		area = &(zone->free_area[current_order]);
		page = get_page_from_free_area(area, migratetype);
		if (!page)
			continue;

		page_del_and_expand(zone, page, order, current_order,
				    migratetype);
		/* ... */
		return page;
	}

	return NULL;
}
```

원하는 크기가 없어서 더 큰 블록을 꺼냈다면 `page_del_and_expand()`가 **쪼갭니다**. 블록을 반으로 갈라 위쪽 절반을 한 단계 아래 목록에 걸고, 남은 절반을 다시 반으로 가르기를 요청한 크기가 될 때까지 되풀이합니다.

돌려받을 때는 반대로 **합칩니다**. 같은 크기의 이웃 블록, 곧 **버디**가 비어 있으면 둘을 합쳐 한 단계 위로 올리고, 거기서 또 버디를 찾습니다. 버디의 위치는 계산으로 나옵니다.

```{.c file="mm/page_alloc.h" line="176"}
static inline unsigned long
__find_buddy_pfn(unsigned long page_pfn, unsigned int order)
{
	return page_pfn ^ (1 << order);
}
```

블록이 항상 자기 크기의 배수 위치에서 시작하므로, PFN의 `order`번 비트만 뒤집으면 버디입니다. 검색도 별도의 자료구조도 필요 없습니다.

::: {.fig src="buddy-split-merge.svg"}
order 0 페이지 하나를 요청했는데 order 3 블록만 남아 있는 경우. 세 번 쪼개 나머지를 각 목록에 걸고, 해제할 때는 버디가 비어 있는 동안 거꾸로 합칩니다.
:::

두 가지 장치가 덧붙어 있습니다.

- **이동 유형**(migratetype). `free_list`가 배열인 이유입니다. 커널 자료구조처럼 옮길 수 없는 페이지(`MIGRATE_UNMOVABLE`)와 유저 페이지처럼 옮길 수 있는 페이지(`MIGRATE_MOVABLE`)를 다른 구역에서 할당합니다. 못 옮기는 페이지가 곳곳에 박히면 그 주변은 영영 큰 블록으로 합쳐지지 못하기 때문입니다. 그래도 조각났을 때는 **컴팩션**(compaction)이 옮길 수 있는 페이지를 한쪽으로 몰아 빈 블록을 만듭니다.
- **CPU별 페이지 목록**(pcp). 작은 요청마다 `zone->lock`을 잡으면 경합이 큽니다. 그래서 CPU마다 빈 페이지를 얼마간 쟁여 두고(`struct per_cpu_pages`), order 3 이하의 요청(과 THP 크기의 요청)은 먼저 여기서 꺼냅니다.

## 할당 경로와 GFP 플래그 {#alloc-path}

`alloc_pages()`는 `__alloc_frozen_pages_noprof()`로 모입니다. 이 함수는 먼저 `get_page_from_freelist()`를 한 번 부릅니다. 존을 차례로 보며 빈 페이지가 `low` 워터마크 위에 있는 존에서 꺼내는 **빠른 경로**입니다. 실패하면 `__alloc_pages_slowpath()`로 갑니다. 느린 경로에서 무엇까지 해도 되는지는 호출한 쪽이 넘긴 **GFP 플래그**가 정합니다.

```{.c file="include/linux/gfp_types.h" line="370"}
#define GFP_ATOMIC	(__GFP_HIGH|__GFP_KSWAPD_RECLAIM)
#define GFP_KERNEL	(__GFP_RECLAIM | __GFP_IO | __GFP_FS)
#define GFP_KERNEL_ACCOUNT (GFP_KERNEL | __GFP_ACCOUNT)
#define GFP_NOWAIT	(__GFP_KSWAPD_RECLAIM | __GFP_NOWARN)
#define GFP_NOIO	(__GFP_RECLAIM)
#define GFP_NOFS	(__GFP_RECLAIM | __GFP_IO)
```

`__GFP_RECLAIM`은 두 비트의 합입니다. `__GFP_KSWAPD_RECLAIM`은 "kswapd를 깨워도 된다", `__GFP_DIRECT_RECLAIM`은 "내가 직접 회수해도 된다"입니다. 뒤쪽은 잠들 수 있다는 뜻입니다.

| 플래그 | 잠드는가 | 쓰는 곳 |
|---|---|---|
| `GFP_KERNEL` | 예 | 태스크 컨텍스트의 일반 할당. 직접 회수, I/O, 파일시스템 호출을 모두 허용 |
| `GFP_ATOMIC` | 아니오 | 인터럽트 핸들러, 스핀락 구간. `__GFP_HIGH`로 `min` 아래 예비분 일부를 씁니다. |
| `GFP_NOWAIT` | 아니오 | 실패해도 되는 기회주의적 할당. 예비분은 쓰지 않습니다. |
| `GFP_NOIO`, `GFP_NOFS` | 예 | 회수는 하되 I/O나 파일시스템으로 다시 들어가지 않게. 블록 계층과 파일시스템 내부용 |

```{.c file="mm/page_alloc.c" line="4783"}
static inline struct page *
__alloc_pages_slowpath(gfp_t gfp_mask, unsigned int order,
						struct alloc_context *ac)
{
	bool can_direct_reclaim = gfp_mask & __GFP_DIRECT_RECLAIM;
	/* ... */
	if (alloc_flags & ALLOC_KSWAPD)
		wake_all_kswapds(order, gfp_mask, ac);
	/* ... */
	page = get_page_from_freelist(gfp_mask, order, alloc_flags, ac);
	if (page)
		goto got_pg;
	/* ... */
	/* Caller is not willing to reclaim, we can't balance anything */
	if (!can_direct_reclaim) {
		/* ... */
		goto nopage;
	}
	/* ... */
		page = __alloc_pages_direct_reclaim(gfp_mask, order, alloc_flags,
							ac, &did_some_progress);
	/* ... */
	page = __alloc_pages_direct_compact(gfp_mask, order, alloc_flags, ac,
					compact_priority, &compact_result);
	/* ... */
	page = __alloc_pages_may_oom(gfp_mask, order, ac, &did_some_progress);
	/* ... */
}
```

느린 경로는 점점 비싼 수단을 차례로 씁니다. kswapd를 깨우고, 워터마크를 `min`으로 낮춰 다시 시도하고, 그래도 없으면 호출한 태스크가 **직접 회수**를 하고, 컴팩션을 하고, 몇 번 되풀이한 끝에 OOM 킬러를 부릅니다. `GFP_ATOMIC`과 `GFP_NOWAIT`은 `can_direct_reclaim`이 거짓이므로 둘째 시도에서 실패하면 곧바로 `NULL`을 받습니다.

::: {.fig src="alloc-paths.svg"}
페이지 할당의 빠른 경로와 느린 경로. 잠들 수 없는 요청은 점선에서 포기하고, `GFP_KERNEL` 요청은 끝까지 내려갑니다.
:::

::: {.warn}
스핀락을 쥔 채, 또는 인터럽트 핸들러에서 `GFP_KERNEL`로 할당하면 안 됩니다. 메모리가 넉넉할 때는 빠른 경로에서 끝나므로 아무 일도 없다가, 메모리가 모자란 날 직접 회수로 들어가 잠들려 하면서 문제가 드러납니다([6장](ch06.html)). 그래서 `kmalloc()`의 진입부에는 `might_alloc()`이 있습니다. 디버그 옵션을 켠 커널은 실제로 잠들지 않아도 "잠들 수 있는 플래그를 원자적 컨텍스트에서 넘겼다"는 사실만으로 경고를 냅니다.
:::

## 슬랩: SLUB과 sheaves {#slub}

커널이 할당하는 것은 대부분 페이지보다 훨씬 작습니다. `task_struct`, 아이노드, 수십 바이트짜리 버퍼입니다. **슬랩 할당자**는 버디에서 받은 페이지를 같은 크기의 객체로 잘라 나눠 줍니다. 객체 종류 하나가 `struct kmem_cache` 하나이고, 객체로 잘라 놓은 페이지 묶음 하나가 **슬랩**(`struct slab`)입니다. `kmalloc()`은 8, 16, 32, 64, 96, 128, 192, 256바이트부터 8KB까지 크기별로 미리 만들어 둔 캐시에서 요청 크기 이상인 가장 작은 것을 고릅니다. 그보다 크면 페이지 할당자로 넘깁니다. 같은 크기의 캐시도 한 벌이 아닙니다. 하드닝 옵션을 켜면 크기마다 캐시를 여러 벌 두어 호출 위치나 타입에 따라 갈라 넣고(`CONFIG_KMALLOC_PARTITION_CACHES`), 유저가 크기를 정할 수 있는 할당은 따로 만든 버킷으로 보냅니다(`CONFIG_SLAB_BUCKETS`). 공격자가 고른 데이터를 표적 객체 바로 옆에 놓기 어렵게 하려는 것입니다.

v7.3의 SLUB은 객체가 지나는 층이 넷입니다.

```{.c file="mm/slub.c" line="421"}
struct node_barn {
	spinlock_t lock;
	struct list_head sheaves_full;
	struct list_head sheaves_empty;
	unsigned int nr_full;
	unsigned int nr_empty;
};

struct slab_sheaf {
	/* ... */
	struct kmem_cache *cache;
	unsigned int size;
	int node; /* only used for rcu_sheaf */
	void *objects[];
};

struct slub_percpu_sheaves {
	local_trylock_t lock;
	struct slab_sheaf *main; /* never NULL when unlocked */
	struct slab_sheaf *spare; /* empty or full, may be NULL */
	struct slab_sheaf *rcu_free; /* for batching kfree_rcu() */
};
```

**sheaf**는 객체 포인터의 배열입니다. CPU마다 `main`과 `spare` 두 개를 갖고, NUMA 노드마다 가득 찬 sheaf와 빈 sheaf를 쌓아 두는 **barn**이 있습니다. 그 아래에 빈 객체가 남은 슬랩의 목록(노드별 partial 목록)이 있고, 맨 아래가 버디 할당자입니다.

::: {.fig src="slub-sheaves.svg"}
v7.3 SLUB의 네 층. 대부분의 `kmalloc()`과 `kfree()`는 맨 위층에서 배열 원소 하나를 넣고 빼는 것으로 끝납니다.
:::

```{.c file="mm/slub.c" line="4826"}
static __fastpath_inline
void *alloc_from_pcs(struct kmem_cache *s, gfp_t gfp, unsigned int alloc_flags, int node)
{
	/* ... */
	if (!local_trylock(&s->cpu_sheaves->lock))
		return NULL;

	pcs = this_cpu_ptr(s->cpu_sheaves);

	if (unlikely(pcs->main->size == 0)) {
		pcs = __pcs_replace_empty_main(s, pcs, gfp, alloc_flags);
		if (unlikely(!pcs))
			return NULL;
	}

	object = pcs->main->objects[pcs->main->size - 1];
	/* ... */
	pcs->main->size--;

	local_unlock(&s->cpu_sheaves->lock);

	stat(s, ALLOC_FASTPATH);

	return object;
}
```

빠른 경로는 이것이 전부입니다. `local_trylock()`은 RT가 아닌 커널에서 선점을 끄는 일만 하고 원자 연산을 쓰지 않습니다. 그 뒤 `main` 배열의 마지막 포인터를 꺼냅니다. `main`이 비었으면 `__pcs_replace_empty_main()`이 `spare`와 맞바꾸고, `spare`도 비었으면 barn에서 가득 찬 sheaf를 받아 오고, barn에도 없으면 partial 슬랩에서 객체를 꺼내 sheaf를 채웁니다. 해제(`free_to_pcs()`)는 거울상입니다. `main`에 포인터를 하나 넣고, 가득 차면 barn으로 보냅니다. `rcu_free`는 `kfree_rcu()`로 넘어온 객체를 모았다가 유예 기간 뒤에 통째로 돌려주는 sheaf입니다([16장](ch16.html)).

::: {.old}
교재는 흔히 슬랩 할당자가 SLAB, SLUB, SLOB 셋이고 빌드할 때 고른다고 설명합니다. SLOB은 6.4에서, SLAB은 6.8에서 지워져 v7.3에는 SLUB만 있습니다. SLUB의 내부도 달라졌습니다. 예전 SLUB은 CPU마다 슬랩 하나를 통째로 붙들고(`kmem_cache_cpu`), 그 슬랩의 빈 객체 리스트를 `this_cpu_cmpxchg_double()`로 락 없이 고쳤습니다. 6.18에 sheaves가 일부 캐시에 선택 사항으로 들어왔고, 7.0에서 모든 캐시가 sheaves를 쓰게 되면서 CPU별 슬랩과 그 빠른 경로가 지워졌습니다. v7.3의 `mm/slub.c`에는 `kmem_cache_cpu`라는 이름이 없습니다.
:::

::: {.design}
구현을 줄이는 것도 설계 결정입니다. 세 할당자는 같은 API 뒤에 있었지만, 새 기능(메모리 cgroup 과금, 하드닝, 디버깅)을 넣을 때마다 세 번 구현하고 세 번 시험해야 했습니다. 메인테이너들은 SLOB이 맡던 아주 작은 시스템을 SLUB의 설정 하나(`CONFIG_SLUB_TINY`)로 덮고, 사라질 구현을 먼저 "폐기 예정"으로 표시해 몇 릴리스를 기다린 뒤 지웠습니다. 하나만 남자 내부를 과감하게 바꿀 수 있게 되었고, 그 결과가 sheaves입니다. 다만 7.0의 전환 직후 특정 부하에서 성능 회귀가 보고되어 다음 릴리스에서 고쳐졌습니다. 가장 뜨거운 경로를 갈아 끼우는 일의 값입니다.
:::

물리적으로 연속할 필요가 없는 큰 메모리는 `vmalloc()`으로 받습니다. 페이지를 하나씩 따로 할당해 [17장](ch17.html)의 vmalloc 영역에 이어 붙여 매핑합니다. 큰 연속 블록을 구하지 못해 실패할 일이 없는 대신 매핑 비용이 듭니다. `kvmalloc()`은 먼저 `kmalloc()`을 시도하고 실패하면 `vmalloc()`으로 넘어갑니다.

돌아가는 시스템에서는 `slabtop -o | head -15`가 캐시를 메모리 사용량 순으로 보여 줍니다. 보통 `dentry`와 `inode_cache`가 위에 있습니다. 캐시 하나의 설정은 `/sys/kernel/slab/<이름>/` 아래의 `object_size`, `objs_per_slab`, `order`에서 봅니다.

## 페이지 캐시와 역매핑 {#pagecache-rmap}

회수를 보기 전에, 물리 페이지를 가리키는 두 가지 연결을 짚어 둡니다.

**페이지 캐시**는 파일의 내용을 담은 폴리오의 모음입니다. 파일(아이노드)마다 `struct address_space`가 하나 있고, 그 안의 `i_pages`가 "파일 안의 오프셋 → 폴리오"를 찾는 xarray입니다. 큰 폴리오는 여러 오프셋을 한 항목으로 덮습니다. 폴리오가 회수되어 빠진 자리에는 포인터 대신 작은 정수값이 남습니다. 뒤에서 볼 그림자 항목입니다. 읽기와 쓰기가 이 캐시를 거치는 경로는 [20장](ch20.html)에서 다룹니다.

**역매핑**(reverse mapping, rmap)은 반대 방향의 길입니다. 페이지 테이블은 "가상 주소 → 물리 페이지"를 알려 주지만, 회수는 "이 물리 페이지를 매핑한 PTE는 어디 어디인가"를 알아야 합니다. 페이지를 거두려면 그 PTE들을 전부 지워야 하기 때문입니다.

::: {.fig src="rmap.svg"}
폴리오에서 PTE까지 거슬러 올라가는 길. `mapping`이 파일이면 `i_mmap` 트리를, 익명이면 `anon_vma`의 트리를 따라 VMA들을 찾고, VMA마다 페이지 테이블을 내려가 PTE에 닿습니다.
:::

출발점은 `folio->mapping`입니다. 파일 폴리오라면 `address_space`를 가리키고, 그 안의 `i_mmap`이 이 파일을 매핑한 VMA들의 구간 트리입니다. 익명 폴리오라면 포인터의 맨 아래 비트가 서 있고 `struct anon_vma`를 가리킵니다. `fork()`로 같은 페이지를 공유하게 된 VMA들이 이 `anon_vma`의 트리에 걸려 있습니다. `rmap_walk()`가 이 길을 걷고, 그 위에서 `folio_referenced()`(누가 최근에 접근했나)와 `try_to_unmap()`(모든 PTE에서 떼어 내기)이 동작합니다.

## 회수 {#reclaim}

**회수**(reclaim)는 쓰이고 있는 페이지를 비워 빈 페이지로 만드는 일입니다. 하는 주체는 둘입니다. 노드마다 있는 커널 스레드 **`kswapd`**는 빈 페이지가 `low` 아래로 내려가면 깨어나 `high`까지 채웁니다. 그것으로 모자라면 할당을 요청한 태스크가 제 시간을 써서 **직접 회수**를 합니다. 직접 회수는 그 태스크의 지연 시간으로 곧바로 나타납니다.

비우는 값은 페이지마다 다릅니다.

| 페이지 | 비우려면 |
|---|---|
| 깨끗한 파일 페이지 | 그냥 버립니다. 필요하면 파일에서 다시 읽습니다. |
| 더러운 파일 페이지 | 먼저 디스크에 써야 합니다. |
| 익명 페이지 | 스왑에 써야 합니다. 스왑이 없으면 못 거둡니다. |
| `mlock()`된 페이지 등 | 거둘 수 없습니다. |

남은 문제는 **어느 것부터**입니다. 곧 다시 쓰일 페이지를 버리면 되읽는 비용이 듭니다. 커널은 "최근에 쓰이지 않은 것이 앞으로도 덜 쓰일 것"이라는 가정으로 고릅니다.

고전적인 방식은 리스트 넷입니다. 익명과 파일 각각에 **active**와 **inactive** 리스트가 있습니다. 새 페이지는 inactive로 들어가고, 거기 있는 동안 다시 접근되면 active로 올라가고, active가 너무 커지면 꼬리가 inactive로 내려옵니다. 회수는 inactive의 꼬리부터 봅니다. 접근 여부는 rmap으로 PTE를 찾아가 `ACCESSED` 비트를 읽어 압니다. 페이지 하나를 판정하려고 rmap을 한 번 걷는 셈입니다.

**MGLRU**(multi-gen LRU)는 둘로 나누던 것을 여러 **세대**로 나눕니다.

```{.c file="include/linux/mmzone.h" line="563"}
struct lru_gen_folio {
	/* the aging increments the youngest generation number */
	unsigned long max_seq;
	/* the eviction increments the oldest generation numbers */
	unsigned long min_seq[ANON_AND_FILE];
	/* the birth time of each generation in jiffies */
	unsigned long timestamps[MAX_NR_GENS];
	/* the multi-gen LRU lists, lazily sorted on eviction */
	struct list_head folios[MAX_NR_GENS][ANON_AND_FILE][MAX_NR_ZONES];
	/* ... */
};
```

세대는 최대 넷(`MAX_NR_GENS`)입니다. 두 가지 일이 번갈아 돕니다. **에이징**은 `max_seq`를 올려 새 세대를 만들고, 그사이 접근된 페이지를 가장 젊은 세대로 옮깁니다. **축출**은 가장 늙은 세대(`min_seq`)의 페이지를 거둡니다. 차이는 접근 여부를 모으는 방법에 있습니다. MGLRU의 에이징은 페이지마다 rmap을 걷는 대신 프로세스의 페이지 테이블을 통째로 훑어 `ACCESSED` 비트가 선 PTE를 한꺼번에 모읍니다. 접근된 페이지는 주소 공간에서 몰려 있는 경향이 있으므로 이쪽이 캐시에 유리합니다.

::: {.fig src="lru-mglru.svg"}
고전 LRU는 리스트 둘 사이를 오가고, MGLRU는 세대 번호가 한 방향으로 흐릅니다. 익명과 파일은 각각 따로 같은 구조를 가집니다.
:::

v7.3에는 두 구현이 함께 들어 있습니다. `shrink_node()`와 `shrink_lruvec()`는 `lru_gen_enabled()`가 참이면 MGLRU 쪽으로, 아니면 고전 리스트 쪽으로 갑니다. 빌드 옵션 `CONFIG_LRU_GEN_ENABLED`는 기본값이 꺼짐이어서, 어느 쪽이 도는지는 배포판에 달려 있습니다.

판단이 틀렸는지도 확인합니다. 파일 폴리오를 버릴 때 xarray의 그 자리에 **그림자 항목**(shadow entry)을 남깁니다. 버린 시점의 정보를 담은 정수입니다. 같은 오프셋이 다시 읽혀 폴트가 나면(**재폴트**), 그림자 항목으로 "버린 지 얼마 만에 돌아왔는가"를 계산합니다. 금방 돌아왔다면 버리지 말았어야 할 페이지이므로 곧바로 보호 대상으로 올리고, 이 통계가 익명과 파일 사이의 회수 비율을 조정하는 데 쓰입니다. `vm.swappiness`(기본 60, 범위 0–200)는 그 비율의 기준점입니다. 값이 클수록 익명 페이지를 스왑으로 내보내는 쪽으로 기웁니다.

::: {.lab}
어느 구현이 도는지, 회수가 얼마나 일어났는지 봅니다.

```console
$ cat /sys/kernel/mm/lru_gen/enabled
0x0007
$ grep -E 'pgscan_(kswapd|direct) |pgsteal_(kswapd|direct) |workingset_refault' /proc/vmstat
pgsteal_kswapd 48211930
pgsteal_direct 10462
pgscan_kswapd 51930014
pgscan_direct 11208
workingset_refault_anon 20417
...
```

`enabled`가 `0x0000`이면 고전 LRU입니다. `pgscan`은 살펴본 페이지 수, `pgsteal`은 실제로 거둔 수입니다. `pgscan_direct`가 빠르게 늘면 kswapd가 따라가지 못해 태스크들이 직접 회수를 하고 있다는 신호입니다. `workingset_refault_*`가 빠르게 늘면 버린 페이지를 곧 되읽는 **스래싱**입니다.
:::

메모리가 모자라기 전에 미리 거두는 길도 있습니다. cgroup v2의 `memory.reclaim` 파일에 양을 쓰면 그만큼 회수합니다. **DAMON**은 메모리 접근 패턴을 낮은 비용으로 표본 조사하는 프레임워크이고, 그 위의 `DAMON_RECLAIM`은 오래 접근되지 않은 영역을 압력이 오기 전에 내보냅니다.

## 스왑 {#swap}

익명 페이지는 돌아갈 파일이 없으므로, 거두려면 내용을 **스왑** 영역에 써 둬야 합니다. 회수가 익명 폴리오를 고르면 스왑 장치의 빈 자리(슬롯)를 배정하고, rmap으로 찾은 PTE들을 "스왑 장치 번호와 슬롯 오프셋"을 담은 **스왑 엔트리**로 바꿉니다. `PRESENT`가 꺼진 PTE의 나머지 비트를 커널이 쓰는 경우입니다. 내용을 장치에 쓰고 나면 폴리오를 해제합니다. 나중에 그 주소에 접근하면 [17장](ch17.html)의 `do_swap_page()`가 엔트리를 보고 읽어 옵니다.

쓰는 중이거나 읽은 직후에는 같은 내용이 메모리와 스왑 양쪽에 있습니다. 이 기간에 스왑 엔트리로 폴리오를 찾는 장치가 **스왑 캐시**입니다. 한 페이지를 여러 프로세스가 공유하다 스왑되었을 때, 먼저 폴트를 낸 쪽이 읽어 온 폴리오를 나머지가 다시 읽지 않고 찾아 쓰게 해 줍니다.

```{.c file="mm/swap_table.h" line="26"}
 * Swap table entry type and bits layouts:
 *
 * NULL:     |---------------- 0 ---------------| - Free slot
 * Shadow:   |SWAP_COUNT|Z|---- SHADOW_VAL ---|1| - Swapped out slot
 * PFN:      |SWAP_COUNT|Z|------ PFN -------|10| - Cached slot
 * Pointer:  |----------- Pointer ----------|100| - (Unused)
 * Bad:      |------------- 1 -------------|1000| - Bad slot
```

v7.3의 스왑 캐시는 **스왑 테이블**입니다. 스왑 장치는 **클러스터**(x86-64에서 보통 512슬롯)로 나뉘고, 클러스터마다 슬롯당 8바이트인 배열이 하나 있습니다. 배열 전체가 정확히 한 페이지입니다. 항목 하나가 슬롯의 상태를 전부 담습니다. 0이면 빈 슬롯, 맨 아래 비트가 `1`이면 스왑에만 있는 상태이고 나머지에 회수 때의 그림자 정보, `10`이면 메모리에도 폴리오가 있는 상태이고 나머지에 그 PFN이 들어 있습니다. 윗비트에는 이 슬롯을 가리키는 스왑 엔트리가 몇 개인지 세는 카운트가 함께 있습니다.

::: {.fig src="swap-table.svg"}
스왑 슬롯 하나가 거치는 상태. 스왑 테이블의 항목 하나가 상태에 따라 0, PFN, 그림자 값으로 바뀝니다.
:::

::: {.old}
예전 자료는 스왑 캐시를 `swapper_spaces`라는 `address_space` 배열로, 곧 페이지 캐시와 같은 xarray로 설명하고, 슬롯마다 참조 횟수를 세는 바이트 배열 `swap_map`을 따로 둡니다. xarray는 트리라서 조회마다 노드 몇 개를 거치고, 넓은 범위가 락 하나를 공유했습니다. 6.18에서 스왑 캐시가 클러스터별 배열로 바뀌었고, v7.3의 `struct swap_info_struct`에는 `swap_map` 필드도 없습니다. 조회는 배열 색인 한 번이고 락은 클러스터 단위입니다.
:::

스왑 장치가 느린 디스크일 필요는 없습니다. **zswap**은 스왑으로 나가려는 페이지를 가로채 압축해서 메모리 안의 풀에 담아 두고, 풀이 차면 오래된 것부터 진짜 스왑 장치로 내보냅니다. **zram**은 압축한 메모리 자체를 블록 장치로 보이게 하는 드라이버여서, 그 위에 스왑을 올리면 디스크 없이 스왑을 씁니다.

## 메모리가 정말 없을 때 {#oom}

회수와 컴팩션을 되풀이해도 페이지를 얻지 못하면 `__alloc_pages_may_oom()`이 `out_of_memory()`를 부릅니다. **OOM 킬러**는 프로세스 하나를 골라 죽여 그 메모리를 통째로 돌려받습니다. 고르는 기준은 짧습니다.

```{.c file="mm/oom_kill.c" line="199"}
long oom_badness(struct task_struct *p, unsigned long totalpages)
{
	/* ... */
	adj = (long)p->signal->oom_score_adj;
	if (adj == OOM_SCORE_ADJ_MIN ||
			mm_flags_test(MMF_OOM_SKIP, p->mm) ||
			in_vfork(p)) {
		task_unlock(p);
		return LONG_MIN;
	}

	/*
	 * The baseline for the badness score is the proportion of RAM that each
	 * task's rss, pagetable and swap space use.
	 */
	points = get_mm_rss_sum(p->mm) + get_mm_counter_sum(p->mm, MM_SWAPENTS) +
		mm_pgtables_bytes(p->mm) / PAGE_SIZE;
	task_unlock(p);

	/* Normalize to oom_score_adj units */
	adj *= totalpages / 1000;
	points += adj;

	return points;
}
```

점수는 그 프로세스가 차지한 메모리의 페이지 수입니다. 물리 메모리(RSS), 스왑에 나가 있는 양, 페이지 테이블을 더합니다. 여기에 `/proc/PID/oom_score_adj`(−1000에서 1000)가 더해집니다. 1이 전체 메모리의 0.1%에 해당하고, −1000이면 후보에서 빠집니다. 점수가 가장 높은 프로세스가 `SIGKILL`을 받습니다.

죽이는 것만으로는 메모리가 바로 돌아오지 않습니다. 희생자가 락을 기다리며 잠들어 있으면 종료 처리가 늦어집니다. 그래서 커널 스레드 **`oom_reaper`**가 희생자의 종료를 기다리지 않고 그 익명 메모리의 매핑을 먼저 걷어 냅니다.

메모리 cgroup이 자기 한도에 걸렸을 때도 같은 코드가 돌되, 후보가 그 cgroup 안의 프로세스로 좁혀집니다([22장](ch22.html)).

::: {.myth}
"OOM 킬러가 돌기 전까지는 시스템이 멀쩡하다." 아닙니다. OOM 킬러는 마지막 수단이고, 거기 이르기 전에 시스템은 이미 한참 동안 직접 회수와 재폴트로 거의 멈춰 있을 수 있습니다. 그래서 **PSI**(pressure stall information)가 "메모리를 기다리느라 태스크가 멈춰 있던 시간의 비율"을 `/proc/pressure/memory`로 내보내고, `systemd-oomd` 같은 유저 공간 데몬이 이 값을 보고 커널보다 먼저 프로세스를 정리합니다.
:::

::: {.lab}
OOM이 났다면 `dmesg`에 보고서가 남습니다. 읽을 줄은 셋입니다.

```console
$ sudo dmesg | grep -iE 'oom|killed process'
stress invoked oom-killer: gfp_mask=0x140dca(...), order=0, oom_score_adj=0
...
Out of memory: Killed process 4127 (stress) total-vm:8413004kB, anon-rss:7902216kB, ...
```

첫 줄은 **누가 요청하다가** OOM이 났는지와 그 요청의 GFP 플래그와 order입니다. 희생자와 다른 프로세스일 수 있습니다. 가운데에는 존별 빈 페이지와 워터마크, 프로세스별 메모리 표가 나옵니다. 마지막 줄이 고른 희생자입니다. 지금의 압력은 `cat /proc/pressure/memory`로 봅니다.
:::

## 정리 {#summary}

- 프레임마다 `struct page`가 있고, 폴리오는 "tail이 아닌 페이지 묶음"이라는 불변식을 타입으로 만든 것입니다. 락, 참조 카운트, LRU는 폴리오 단위입니다.
- 버디 할당자는 order별 빈 목록을 두고, 큰 블록을 반씩 쪼개 내주고 버디가 비면 합칩니다. 버디의 위치는 PFN의 비트 하나를 뒤집어 구합니다.
- 할당은 빠른 경로에서 실패하면 kswapd 깨우기, 직접 회수, 컴팩션, OOM으로 내려갑니다. GFP 플래그가 어디까지 내려갈 수 있는지를 정합니다.
- v7.3의 슬랩 할당자는 SLUB 하나이고, 빠른 경로는 CPU별 sheaf 배열에서 포인터를 넣고 빼는 것입니다.
- 회수는 rmap으로 PTE를 찾아 떼어 냅니다. 무엇을 먼저 버릴지는 고전 LRU나 MGLRU가 정하고, 그림자 항목으로 재폴트를 감지해 판단을 고칩니다.
- 스왑 캐시는 클러스터별 배열인 스왑 테이블입니다. 항목 하나가 슬롯의 상태와 참조 횟수를 함께 담습니다.
- OOM 킬러는 RSS, 스왑, 페이지 테이블을 더한 값에 `oom_score_adj`를 반영해 희생자를 고릅니다.

## 확인 문제 {#quiz}

::: {.q}
PFN 12에서 시작하는 order 2 블록이 해제되었습니다. 버디는 어느 PFN에서 시작합니까? 버디도 비어 있어 합쳐진 order 3 블록의 시작 PFN과, 그 블록의 버디는 각각 무엇입니까?

::: {.a}
order 2의 버디는 `12 ^ (1 << 2) = 12 ^ 4 = 8`입니다. 합치면 둘 가운데 작은 쪽인 PFN 8에서 시작하는 order 3 블록이 됩니다. `__free_one_page()`는 이것을 `combined_pfn = buddy_pfn & pfn`으로 구합니다. 그 블록의 버디는 `8 ^ (1 << 3) = 0`입니다. PFN 0–7이 비어 있으면 다시 합쳐 order 4가 됩니다.
:::
:::

::: {.q}
네트워크 드라이버의 인터럽트 핸들러가 `kmalloc(size, GFP_ATOMIC)`을 부릅니다. 빈 페이지가 `low`와 `min` 사이에 있을 때와 `min` 바로 아래에 있을 때, 이 요청은 각각 어떻게 됩니까? 같은 상황에서 `GFP_NOWAIT`은 어떻게 다릅니까?

::: {.a}
대부분은 CPU별 sheaf에서 끝나 페이지 할당자까지 가지 않습니다. 슬랩이 새 페이지를 필요로 할 때가 문제입니다. `low`와 `min` 사이라면 빠른 경로는 `low`를 기준으로 하므로 실패하고, 느린 경로가 kswapd를 깨운 뒤 `min` 기준으로 다시 시도해 성공합니다. `min` 아래라면 `GFP_ATOMIC`의 `__GFP_HIGH`가 예비분 일부를 쓰게 해 주므로 여전히 성공할 수 있습니다. 그마저 없으면 `can_direct_reclaim`이 거짓이라 `NULL`을 돌려받습니다. `GFP_NOWAIT`은 `__GFP_HIGH`가 없어서 `min` 아래로는 내려가지 못하고 더 일찍 실패합니다.
:::
:::

::: {.q}
v7.3에서 한 CPU가 같은 캐시의 객체를 `kfree()`만 계속하면, 객체는 어떤 순서로 어느 층까지 내려갑니까?

::: {.a}
처음에는 `free_to_pcs()`가 `main` sheaf에 포인터를 넣습니다. `main`이 가득 차면 `spare`와 바꾸고, 둘 다 차면 가득 찬 sheaf를 barn의 `sheaves_full`에 넘기고 빈 sheaf를 받아 옵니다. barn에는 가득 찬 sheaf를 쌓아 둘 수 있는 한도가 있습니다. 그 한도에 닿으면 sheaf의 객체를 원래의 슬랩으로 돌려보냅니다. 슬랩의 객체가 전부 돌아와 빈 슬랩이 되면 페이지가 버디 할당자로 돌아갑니다.
:::
:::

::: {.q}
고전 LRU와 MGLRU는 "이 페이지가 최근에 접근되었는가"를 각각 어떻게 알아냅니까? 메모리가 큰 시스템에서 이 차이가 왜 중요합니까?

::: {.a}
고전 LRU는 살펴볼 페이지마다 rmap을 걸어 그 페이지를 매핑한 PTE들의 `ACCESSED` 비트를 읽습니다. 페이지 하나에 rmap 한 번이고, 서로 관계없는 페이지 테이블을 건너다니므로 캐시 적중이 나쁩니다. MGLRU의 에이징은 프로세스의 페이지 테이블을 순서대로 훑어 `ACCESSED`가 선 PTE를 한꺼번에 모으고, 그 페이지들의 세대 번호를 올립니다. 페이지 수가 수억 개에 이르면 판정에 드는 CPU 시간 자체가 kswapd의 병목이 되므로, 접근 정보를 모으는 비용의 차이가 회수 속도의 차이가 됩니다.
:::
:::

::: {.q}
스왑 테이블의 항목이 `PFN` 형태에서 `Shadow` 형태로 바뀌는 때와, 그 반대로 바뀌는 때는 각각 언제입니까?

::: {.a}
`PFN`에서 `Shadow`로: 스왑 아웃이 끝났을 때입니다. 폴리오의 내용이 스왑 장치에 다 쓰이고 폴리오가 스왑 캐시에서 빠지면, 그 자리에 회수 시점의 정보를 담은 그림자 값이 남습니다. `Shadow`에서 `PFN`으로: 스왑 인이 시작될 때입니다. `do_swap_page()`가 새 폴리오를 할당해 스왑 캐시에 넣으면 항목이 그 폴리오의 PFN으로 바뀌고, 이때 꺼낸 그림자 값은 재폴트 판정에 쓰입니다.
:::
:::

## 용어 {#terms}

::: {.terms}
폴리오 (folio)
:   tail이 아닌 페이지에서 시작하는, 2의 거듭제곱 개의 연속한 페이지 묶음. 홑 페이지도 폴리오다.

존 (zone)
:   노드 안에서 주소 범위와 용도에 따라 나눈 물리 메모리 구역.

워터마크 (watermark)
:   존의 빈 페이지 수에 대한 기준선. `min`, `low`, `high`.

버디 할당자 (buddy allocator)
:   빈 메모리를 2^order^ 페이지 블록으로 관리하며 쪼개고 합치는 페이지 할당자.

GFP 플래그
:   할당 요청이 잠들어도 되는지, 어느 존을 쓰는지, 실패 시 어떻게 할지를 알리는 비트.

슬랩 (slab)
:   같은 크기의 객체로 잘라 놓은 페이지 묶음. `struct slab`.

sheaf
:   SLUB이 CPU마다 두는 객체 포인터 배열. 가득 찬 것과 빈 것을 노드별 barn과 주고받는다.

역매핑 (reverse mapping)
:   물리 페이지에서 그것을 매핑한 모든 PTE를 찾아가는 길.

회수 (reclaim)
:   쓰이는 페이지를 비워 빈 페이지로 만드는 일. kswapd의 회수와 직접 회수가 있다.

MGLRU
:   페이지를 여러 세대로 나누고 페이지 테이블 훑기로 접근 정보를 모으는 회수 알고리즘.

그림자 항목 (shadow entry)
:   회수된 폴리오의 자리에 남겨 두는 값. 재폴트가 났을 때 얼마 만에 돌아왔는지 계산하는 데 쓴다.

스왑 테이블 (swap table)
:   스왑 클러스터마다 있는 배열. 슬롯별 스왑 캐시 상태와 참조 횟수를 담는다.
:::
